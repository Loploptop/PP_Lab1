# Lab1 — метод трапеций (POSIX threads и std::thread)

Лабораторная работа: вычислить определённый интеграл методом трапеций двумя
способами — средствами POSIX (`pthread_create` / `pthread_join`) и средствами
`std::thread`.

Подынтегральная функция выбрана самостоятельно:

```
f(x) = exp(-x^2)          на отрезке [0; 1]
эталон: (sqrt(pi)/2)*erf(1) = 0.746824132812427...
```

## Сборка
Открыть `Lab1.sln` и собрать (Debug|Win32 или Release|Win32).

Платформа — **только Win32 (x86)**: библиотека `pthreadVCE2.lib`
32-разрядная, под x64 компоновка не пройдёт.

## Запуск

```
Lab1                     10000000 шагов
Lab1 1000000             1000000 шагов
Lab1 h=0.0001            шаг 0.0001
```

Пределы интегрирования заданы в программе (`kA`, `kB`), а число шагов или
величина шага — аргументом командной строки (без аргумента берётся 10000000
шагов). Расчёт выполняется для **1, 2, …, 8 потоков** сразу, результаты
выводятся таблицей: время и ускорение для обоих вариантов.

Ускорение показывает, во сколько раз быстрее посчитано по сравнению с одним
потоком: `ускорение(N) = время_в_1_поток / время_в_N_потоков`. Идеальное
значение для N потоков — ровно N.

Пример вывода:

```

Шагов: 10000000, шаг h = 1e-07

Замеров на точку: 7, в таблице показано лучшее (минимальное) время.
Ускорение = время в 1 поток / время в N потоков (идеал для N потоков: N).

потоков |    POSIX, с | ускорение | std::thread, с | ускорение
--------+-------------+-----------+----------------+-----------
      1 |    0.140409 |      1.00 |       0.120673 |      1.00
      2 |    0.061002 |      2.30 |       0.062399 |      1.93
      3 |    0.045566 |      3.08 |       0.043297 |      2.79
      4 |    0.035094 |      4.00 |       0.039357 |      3.07
      5 |    0.043395 |      3.24 |       0.042040 |      2.87
      6 |    0.039313 |      3.57 |       0.038742 |      3.11
      7 |    0.038172 |      3.68 |       0.038356 |      3.15
      8 |    0.034575 |      4.06 |       0.034653 |      3.48

Значение интеграла: POSIX 0.746824169600292, std::thread 0.746824169600292
Эталонное значение: 0.746824132812427
Погрешность метода на 10000000 шагах: 4.926e-06 %
Максимальное расхождение значения между числом потоков: 9.359e-14
```

Время зависит от числа шагов и от загрузки машины, поэтому абсолютные
значения при повторном запуске будут другими — важна общая картина: время
падает примерно до числа физических ядер, дальше выигрыш почти пропадает,
потому что потоки начинают делить одни и те же ядра. По той же причине
ускорение иногда выглядит больше числа потоков: при одном потоке ядро
работает на повышенной частоте (турбо-буст), а при полной загрузке частота
снижается.

Значение интеграла не зависит от числа потоков: расхождение `9.4e-14` — на
уровне точности `double`. Отличие от эталона (`4.9e-06 %`) — это погрешность
самого метода трапеций порядка `O(h²)`.

## Как распределяется работа

Отрезок делится на `steps` элементарных отрезков, шаг `h = (b - a) / steps`.
Отрезки раздаются потокам почти поровну (разница не более одного). Поток
считает сумму значений функции в узлах своего участка — от `firstStep + 1` до
`lastStep` включительно. Узел на стыке двух участков считается только один раз
(в том участке, где он правый конец), поэтому в общей сумме он входит с полным
весом `h`; делить на 2 нужно только концы `a` и `b`:

```
I = h * ( f(a)/2 + сумма_всех_частичных_сумм + f(b)/2 )
```

Оба варианта считают одно и то же, поэтому результаты совпадают.

## Вывод кириллицы

Русский текст в исходниках хранится в UTF-8 (в проекте включён ключ `/utf-8`).
Стандартная консоль Windows работает в CP866, поэтому в начале работы
программа переключает её на UTF-8 вызовом `SetConsoleOutputCP(CP_UTF8)` —
после этого русский текст выводится правильно. При перенаправлении вывода в
файл байты остаются корректным UTF-8.

Если русский текст всё же отображается неверно, дело в шрифте консоли:
нужен шрифт с поддержкой кириллицы (Consolas или Lucida Console). Сменить
можно так: правый клик по заголовку окна → «Свойства» → вкладка «Шрифт».

## Требования задания

* **POSIX** — частичная сумма возвращается потоком, главный поток принимает её
  через второй параметр `pthread_join` (второй аргумент — `void**`). Значение
  размещается в динамической памяти: адрес локальной переменной возвращать
  нельзя, к моменту `join` её уже нет.
* **std::thread** — параметры функции потока передаются по отдельности
  (6 отдельных аргументов, без структуры); результат возвращается через
  выходной параметр `double&`.

## О библиотеке pthread

Используется библиотека из папки задания: pthreads-win32 2.9.1
(`pthread.h`, `pthreadVCE2.lib`, `pthreadVCE2.dll`). Её файлы скопированы в
[third_party/pthreads-win32](third_party/pthreads-win32) и лежат только внутри
проекта. После сборки `pthreadVCE2.dll` автоматически копируется рядом с
`Lab1.exe`.
